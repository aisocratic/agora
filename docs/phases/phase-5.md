# Phase 5 — Suggestions inbox

Status: implemented and verified locally. No commit, push or deployment performed by this phase.

## Delivered

- Append-only migration `004_suggestions.sql`: authenticated attribution, immutable original proposal, latest reviewed draft, versioned pending/accepted/dismissed state, stable accepted card ID and retained decision history.
- Protected submit/list/detail/review/accept/dismiss endpoints. Tokens can propose and read; human session/local/proxy principals review. Request bodies cannot forge attribution.
- Acceptance through `transactBoard`: checks both suggestion version and board revision, validates the live workflow and relationships, then creates the card and finalizes the suggestion atomically. Identical accepted retries return the existing card. Competing acceptance/dismissal produces one terminal outcome; database failure rolls everything back.
- Shared-mode inbox with pending count, filters/pagination, original proposal, rich editable task fields, saved review drafts, dismissal notes and accepted-card navigation. Visible-tab polling updates counts. Stale versions and failed requests preserve edits; explicit refresh loads current versions without replacing the draft. GitHub Pages local mode remains independent.
- Dependency-free CLI `suggest`, `suggestions list`, and `suggestions get`, using the same authenticated HTTP contract. Human review remains a browser operation.

## Handoff

`lib/server/suggestions-repository.ts` is the storage contract; `lib/server/suggestions-http.ts` centralizes route policy and parsing. `components/suggestions/inbox.tsx` accepts the current board/workflow plus refresh and accepted-card callbacks. Its sole shared-board toolbar mount preserves the existing editor and dispatch UI. `BoardController.refresh` is now optional in the interface, matching the remote implementation.

Migration 004 is reserved by this phase; later changes must use new migrations. The server inbox depends on a migrated database. Reviewed history stores the original and latest saved/reviewed draft plus final decision; it does not retain every intermediate draft revision. See [SUGGESTIONS.md](../SUGGESTIONS.md) for the HTTP, limits and retry contract.
