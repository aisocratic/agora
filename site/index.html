Why

Why it exists

The dependency graph is the point.

Cards declare prerequisites. Agora computes waves of genuinely-unblocked work, so parallel agents don't collide and nothing starts before what it depends on is real.

Review is a gate, not a column.

needs_human_review blocks work before it starts; automerge governs only the merge at the end. The two are deliberately separate, because "I want to look at this first" and "you may merge this without me" are different questions.

Agents get an API and a CLI, not a scraper.

Everything the web UI does is a documented HTTP endpoint with token auth. agora board --json returns the board as JSON; the planner extends that response.

You own the data.

One Postgres database, plain SQL, no ORM, no vendor. The queries are SQL you can paste into psql.

Agents

The agent workflow

The CLI is an HTTP client, never a database client — it needs a token and a URL, not Postgres credentials. It ships as a single dependency-free file. Copy cli/agora.mjs or install its locally packed tarball to use it outside the application clone. See the CLI guide; no npm registry release is claimed.

agora skill install drops a Claude Code skill into your project that teaches an agent the whole loop — pick a card, work it, open a PR, respect the review gate. Epics are containers; only leaf tasks are units of work. Cards a human has assigned to themselves are never touched, and they still block their dependents.

Dispatch

Dispatch adapters

Agora does not run agents. It tells something else to, through one small adapter interface.

Dispatch adapters and what each one does
Adapter What it does
none Default — no dispatch, a purely human board.
webhook POSTs the card and its context to a URL you control, HMAC-signed.
command Runs a process on the server. Opt-in, because it executes code.
github-workflow Triggers a workflow_dispatch.

Claude Code and Codex ship as ~15-line examples in examples/dispatch/, not as built-in adapters — vendor CLI flags churn faster than releases.

Configuration

agora.config.ts at the repo root holds the column and type labels, the people who can be assigned, whether the agent half is enabled, and the values your effort / model / harness fields accept. Changing that vocabulary never requires a migration.

Your data

Saved in your browser

Your current board is private to this browser and device. Cards are stored locally; they are not sent to a server or shared with other visitors. Export a backup before clearing your browser data.

The self-hosted application supports a shared PostgreSQL board with password, API-token and trusted-proxy access. This public Pages board stays on your device. The self-hosted app includes dependency planning, dispatch adapters and a human-reviewed suggestions inbox.
